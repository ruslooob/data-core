# Поиск аномалий

Аномалия (см. [GLOSSARY.md](GLOSSARY.md)) — это отправная точка работы аналитика, а не результат. Документ описывает методологию: как от найденной аномалии прийти к строгой проверке через бэктест.

## Цикл работы

1. **Гипотеза.** Аналитик формулирует, что в его представлении аномально: «после события X цена тикеров отрасли Y систематически падает», «всплеск объёма после Z повторяется чаще, чем это можно объяснить случайностью».

2. **Поиск в истории.** Аналитик пишет PQL-запрос, который возвращает все случаи, попадающие под критерий. Результат — таблица прецедентов с метриками. Здесь же — сортировка, взгляд на распределение, проверка, что находок достаточно для разговора о паттерне.

3. **Проверка воспроизводимости.** Если паттерн повторяется на достаточном числе случаев — переход к шагу 4. Если выборка единичная — это шум; гипотеза отбрасывается или уточняется.

4. **Перевод в стратегию.** Найденный PQL-критерий формализуется как `trigger_sql` правила в редакторе сущностей бэктеста (EntityEditor). Условие, по которому аналитик отбирал прецеденты вручную, теперь срабатывает на каждом тике бэктеста.

5. **Бэктест.** Гипотеза проверяется как стратегия: видит ли она аномалию в реальном времени, а не задним числом? Бэктест ловит то, что на ручном просмотре прецедентов не видно: ложные срабатывания, проскальзывание сделок, изменение характера паттерна со временем.

Без проведённого с найденной аномалией бэктеста её нельзя считать подтверждённой закономерностью — пока это только гипотеза, основанная на ретроспективном наблюдении.

## Базовые формы запроса

В PQL есть TA-функции для расчёта реакции цены и объёма — на их основе и пишутся запросы поиска. Простейшая форма — события тикера, у которых аномальная доходность вышла за порог:

```sql
SELECT date_start, event,
       car(tag, date_start) AS car
FROM tagged_events
WHERE tag = 'LKOH'
  AND ABS(car(tag, date_start)) > 0.03
ORDER BY ABS(car) DESC;
```

PQL — это стандартный SQL, поэтому критерии комбинируются через JOIN по тегам сектора, агрегации по дате, отбор через `CASE WHEN`. Полный список TA-функций, их сигнатуры, видимая схема и встроенные шаблоны — в [SPEC_PRECEDENT_LANGUAGE.md](SPEC_PRECEDENT_LANGUAGE.md).
