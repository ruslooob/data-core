# Спецификация: фронтенд для событийного анализа

> Этот документ описывает **что** делает фронтенд и **зачем** — на языке [глоссария](GLOSSARY.md). Он намеренно не содержит реализационных деталей: имён функций, файлов, библиотек, чисел-констант, алгоритмов. Всё это живёт в коде и должно читаться оттуда. Цель спеки — оставаться валидной при любом рефакторинге.

---

## 1. Назначение

Фронтенд — рабочее место финансового аналитика. Пользователь:

1. Выкладывает на полотно нужные виджеты (графики цен, графики индексов, виджет событийного анализа, виджет поиска аномалий, виджет редактора PQL-запросов).
2. Объединяет их в логические группы для совместного исследования.
3. Назначает ведущий график — то, что является объектом исследования.
4. Запускает событийный анализ и интерпретирует результат (AR, CAR, доверительный интервал).
5. Ищет интересные события через язык поиска прецедентов (произвольные SQL-подобные запросы) или через виджет поиска аномалий и переходит к точечному анализу найденных.

---

## 2. Архитектура верхнего уровня

Система состоит из двух компонентов:

- **Клиент** — приложение, в котором пользователь работает с виджетами на полотне. Содержит всю UI-логику, состояние, синхронизацию виджетов и расчёты, не требующие доступа к данным.
- **Сервер данных** — тонкая обёртка над пакетом `core/`. Отвечает за: список тикеров, ряды цен, ряды индексов рынка, события, расчёт событийного анализа, поиск аномалий. Не хранит состояния, не имеет авторизации, не обслуживает несколько пользователей. Каждый запрос — независимый вызов соответствующей функции `core/`.

Граница между ними — REST-API с JSON-телами. Контракт API не фиксируется в этой спеке (он живёт в автогенерируемой документации сервера).

---

## 3. Полотно и виджеты

**Полотно** — единственная рабочая область приложения. Содержит произвольное количество **виджетов**, которые пользователь свободно располагает, перемещает, изменяет в размере, закрывает и поднимает на верхний слой.

Над полотном находится **тулбар** с глобальными командами — в первую очередь добавление нового виджета.

---

## 4. Типы виджетов

### График цены

**Назначение:** показать ряд цен одной акции и (если он ведущий) события на ней.

**Содержит:** выбор тикера, кривую цены, опционально — гистограмму объёма.

**Основная роль в исследовании:** объект исследования. Именно график цены обычно делают ведущим в группе, чтобы привязать к нему виджет событийного анализа.

**События на ведущем графике:** график цены сам по себе **не** загружает события и не рисует их. Это делает виджет событийного анализа той же группы — через переключатель «показать события» (см. ниже). Когда переключатель включён, на ведущем графике появляются маркеры всех событий для его тикера.

**Реакции:**
- Маркеры событий интерактивны: при наведении показывают информацию о событии, при клике выбирают это событие во всех виджетах событийного анализа группы.
- На активное событие группы — подсвечивает t=0 и границы окна события *(только если этот график — ведущий)*.
- На команду зума от группы — изменяет видимый диапазон.
- На hover из CAR — устанавливает crosshair на соответствующий торговый день.

### График индекса

**Назначение:** показать ряд значений индекса рынка (или иного макропоказателя) для контекста — «как двигался рынок в дни события».

**Отличия от графика цены:** не привязан к конкретной акции, не показывает события (они на индексе бессмысленны), не публикует тикер в логическую группу. Не может стать источником тикера для виджета событийного анализа.

**Может быть ведущим** наравне с графиком цены, если пользователь явно этого хочет (например, исследование в основном идёт через индекс).

### Виджет событийного анализа

**Назначение:** провести событийный анализ для выбранного наблюдения эффекта события и показать результат.

**Входы:** наблюдение эффекта события (тикер + событие), модель ожидаемой доходности, окно события, длина оценочного окна, фильтрация выбросов в оценочном окне.

**Выход:** кривая CAR, доверительный интервал, отметка t=0 на оси относительных торговых дней.

**Параметры оценочного окна:** длина (торговых дней) и фильтрация выбросов (мягкий / средний / жёсткий / выкл). Параметры визуально отделены от параметров окна события.

**Привязка к ведущему графику группы:** виджет событийного анализа не выбирает тикер сам — тикер берётся из ведущего графика своей группы. Сценарии:

| Состояние группы | Поведение виджета |
|---|---|
| Группа `none` (виджет автономен) | Полностью самостоятельный: тикер выбирается из общего списка |
| В группе есть ведущий с тикером | Тикер форсится из ведущего, выбор недоступен |
| В группе нет ведущего, либо ведущий — график индекса | Виджет блокируется заглушкой: «выберите ведущий график цены» |

**Реакции и публикации:**
- Запуск расчёта (вручную или навигацией по событиям) публикует **активное событие** в группу — это изменяет подсветку на ведущем графике и графиках индекса группы и инициирует **зум графиков группы** на окно события.
- Hover на CAR публикует **дату для подсветки** — графики группы передвигают свой crosshair.
- Выбор события «извне» (клик по маркеру на графике цены) автоматически переключает анализ на это событие и пересчитывает.

**Переключатель «показать события на ведущем графике»** *(toggle eye)*: дополнительная кнопка в управлении виджетом, которая включает/выключает отображение всех событий тикера ведущего графика. Свойства:

- Состояние **общее на всю группу** — все виджеты событийного анализа в одной группе синхронно отображают одно и то же значение переключателя. Клик по «глазику» в любом из них меняет состояние сразу для всех.
- Когда включён — на ведущем графике появляются маркеры всех событий, для которых найдены данные по тикеру ведущего.
- По умолчанию выключен.
- Disabled, если в группе нет ведущего, либо ведущий — график индекса (нет тикера для показа), либо группа `none`.

### Виджет поиска аномалий (Anomaly Detector)

**Назначение:** автоматическая проверка событий на аномальное поведение цены и объёма.

**Содержит:** выбор тикеров (комбобокс с множественным выбором и поиском), выбор модели ожидаемой доходности, настройки окон (раскрывающаяся панель), кнопка «Сканировать».

**Выход:** таблица событий с метриками (CAR, коэффициент волатильности, коэффициент объёма), флагами обнаруженных аномалий и баллом аномальности. Результаты отсортированы по баллу.

**Взаимодействие с группой:** клик по строке в таблице публикует выбор события в группу — виджет событийного анализа той же группы переключается на это событие.

### Виджет редактора прецедентных запросов (PQL Editor)

**Назначение:** инструмент для исследовательских и поисковых задач — найти интересные события по произвольным критериям и сравнить их по вычисляемым метрикам реакции (CAR и т.п.).

**Содержит:** редактор кода с подсветкой SQL, кнопку выполнения, панель статуса/ошибок, табличный вывод результата. Поверх редактора — иконки сохранения текущего запроса и загрузки сохранённого. Все запросы сохраняются между сессиями (см. [SPEC_PRECEDENT_LANGUAGE.md](SPEC_PRECEDENT_LANGUAGE.md)).

**Входы:** текст запроса на языке поиска прецедентов; имена сохранённых запросов.

**Выход:** таблица — динамические колонки и строки определяются `SELECT`-списком запроса.

**Реакции:** в текущей итерации виджет автономен — не публикует и не слушает сигналы группы. Интеграция с логической группой (например, трансляция найденного набора событий в группу) — будущее расширение.

---

## 5. Логические группы и роль ведущего

### Группа

Логическая группа объединяет виджеты в смысловой блок «мы исследуем это вместе». Пять допустимых значений группы (`none`, плюс четыре цвета) — это идентификаторы, а не уровни важности. Группа `none` означает «виджет автономен».

Виджеты одной группы:

1. Совместно используют **контекст исследования** (см. ниже).
2. Могут участвовать в синхронизации навигации — но только при наличии ведущего.

### Ведущий и ведомые

В каждой непустой группе одновременно может находиться **не более одного ведущего графика**. Ведущим назначается любой график (цены или индекса) явным действием пользователя; снятие — таким же явным действием или сменой группы.

**Если ведущий есть** — все остальные графики становятся ведомыми и автоматически повторяют за ним:
- видимый временной диапазон (масштаб + положение по оси времени);
- позицию crosshair (курсор пользователя).

Других каналов в синхронизации навигации нет. Между собой ведомые не общаются — связь только односторонняя «ведущий → ведомые».

**Если ведущего нет** — графики группы независимы. Никакая навигационная синхронизация не происходит, даже если они в одной группе. Это основной способ «отключить» синхронизацию: снять ведущего.

**Инварианты:**
- В группе `none` ведущего быть не может.
- Если ведущий покидает группу (сменил цвет, был закрыт), его лидерство снимается автоматически — ведомые перестают быть ведомыми.
- Контекст исследования (см. ниже) работает в группе **независимо от наличия ведущего**.

---

## 6. Контекст исследования

«Контекст исследования» — это набор каналов, через которые виджеты группы передают друг другу не *навигационные*, а *смысловые* сигналы. Эти каналы работают в любой непустой группе вне зависимости от того, есть ли в ней ведущий.

| Канал | Кто публикует | Кто реагирует | Что происходит |
|---|---|---|---|
| Активное событие группы | Виджет событийного анализа | Ведущий график цены группы + все графики индекса группы | Подсвечивают t=0 и границы окна события |
| Запрос зума на окно события | Виджет событийного анализа | Графики группы | Изменяют видимый диапазон под окно события |
| Подсветка даты при наведении на CAR | Виджет событийного анализа | Графики группы | Перемещают crosshair на соответствующий торговый день |
| Выбор события | Ведущий график цены (по клику на маркер) или виджет поиска аномалий | Все виджеты событийного анализа группы | Переключаются на это событие и пересчитывают |
| Показ событий на ведущем графике | Виджет событийного анализа (toggle) | Ведущий график цены группы | Загружает и отображает маркеры всех событий своего тикера |

Эти каналы **не зависят** от ведущего: даже если синхронизация навигации в группе выключена (ведущего нет), контекст исследования всё равно распространяется. Это разные смысловые слои: ведущий отвечает за «куда мы смотрим», контекст — за «что мы исследуем».

---

## 7. Поведенческие принципы

- **Никакого глобального состояния**, кроме состава виджетов на полотне. Все взаимодействия — через явные группы.
- **Виджет одного типа можно создавать сколько угодно раз.** Группы, ведущий, контекст — всё работает с произвольным числом виджетов.
- **Ничего не сохраняется между сессиями.** Перезагрузка полотна = чистый старт.
- **Сервер данных не хранит состояния пользователя.** Каждый запрос самостоятелен.
