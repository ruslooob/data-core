# Спецификация: виджет фильтра событий (Event Filter)

## Назначение

Центральный источник событий для логической группы. Пользователь формирует набор событий через SQL-подобный запрос и/или ручную корректировку. Этот набор используется всеми остальными виджетами группы (event study, anomaly scanner, robustness check).

---

## Привязка к группе

Фильтр событий привязан к логической группе. Каждая группа может иметь свой набор событий. Пример:
- Красная группа: «дивиденды LKOH» (10 событий)
- Синяя группа: «санкции по энергосектору» (25 событий)

В группе `none` фильтр событий не работает (виджет автономен).

---

## Workflow

1. Пользователь открывает виджет фильтра событий, назначает его группе
2. Пишет запрос на DSL (см. [ANOMALY_DSL.md](ANOMALY_DSL.md)):
   ```sql
   SELECT * FROM events
   WHERE HAS_TAG('LKOH') AND HAS_TAG('DIVIDEND')
   ```
3. Получает список событий с чекбоксами
4. Вручную снимает/добавляет чекбоксы для точечной корректировки
5. Результирующий набор событий транслируется в группу — все виджеты группы работают с этим набором

---

## Взаимодействие с другими виджетами

| Виджет | Как использует набор событий |
|--------|------------------------------|
| Event Study | Навигация ← → только по событиям из набора. Тикер определяется ведущим графиком (как сейчас) |
| Anomaly Scanner | Сканирует только события из набора вместо «все дивиденды тикера» |
| Robustness Check | Агрегирует CAR только по событиям из набора |
| Price Chart | Маркеры событий — только из набора (когда «глазик» включён) |

## Будущее развитие

- Сохранение запросов как именованных фильтров для переиспользования между сессиями
- Автодополнение тегов в строке запроса
- Предпросмотр количества событий до выполнения запроса
