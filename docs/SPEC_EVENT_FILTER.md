# Спецификация: виджет фильтра событий (Event Filter)

> **Статус:** запланированное расширение поверх существующего PQL-редактора. Нынешний виджет PQL-редактора уже умеет искать события по произвольным критериям, но не умеет передавать набор найденных событий в логическую группу. Этот документ описывает, как PQL-редактор превратится в «фильтр событий», когда мы вернёмся к интеграции с группой.

## Назначение

Центральный источник событий для логической группы. Пользователь формирует набор событий через язык поиска прецедентов (см. [SPEC_PRECEDENT_LANGUAGE.md](SPEC_PRECEDENT_LANGUAGE.md)) и/или ручную корректировку, после чего этот набор используется всеми остальными виджетами группы (event study, robustness check).

---

## Привязка к группе

Фильтр событий привязан к логической группе. Каждая группа может иметь свой набор событий. Пример:
- Красная группа: «дивиденды LKOH» (10 событий)
- Синяя группа: «санкции по энергосектору» (25 событий)

В группе `none` фильтр событий не работает (виджет автономен).

---

## Workflow

1. Пользователь открывает виджет, назначает его группе.
2. Пишет запрос на языке поиска прецедентов:
   ```sql
   SELECT events.id, events.date_start, events.event
   FROM events
   JOIN event_tags ON event_tags.event_id = events.id
   JOIN tags        ON tags.code      = event_tags.tag_code
   WHERE tags.code = 'LKOH'
   ```
3. Получает список событий с чекбоксами.
4. Вручную снимает/добавляет чекбоксы для точечной корректировки.
5. Результирующий набор событий транслируется в группу — все виджеты группы работают с этим набором.

---

## Взаимодействие с другими виджетами

| Виджет | Как использует набор событий |
|--------|------------------------------|
| Event Study | Навигация ← → только по событиям из набора. Тикер определяется ведущим графиком (как сейчас) |
| Robustness Check | Агрегирует CAR только по событиям из набора |
| Price Chart | Маркеры событий — только из набора (когда «глазик» включён) |

---

## Будущее развитие

- Сохранение «фильтров» как именованных шаблонов между сессиями (можно переиспользовать существующий механизм сохранения PQL-запросов).
- Автодополнение тегов и колонок в редакторе запроса.
- Предпросмотр количества событий до выполнения запроса.
