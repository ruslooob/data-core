# Спецификация: Интерактивный Event Study (ноутбук 22)

## Цель

Dash-приложение внутри Jupyter-ноутбука для анализа влияния одного события на котировки акции.
Пользователь выбирает событие и параметры — приложение строит event-study график и показывает ключевые метрики.

---

## Источник данных

- **События:** `data/stocks/dividends_all.csv`
  - Колонки: `ticker`, `announcement_date`, `payment_date`, `dividend_per_share`, `year`
  - t=0 = `announcement_date` (дата объявления — информационное событие)
  - `payment_date` игнорируется
- **Котировки:** через `get_stock_data(ticker)` из `core/stock_data_provider.py`
- **ИПЦ:** через `load_normalized_ipc_data()` из `core/cpi_data_provider.py`
- **Рыночный индекс (IMOEX):** для моделей `market_model` и `capm`
- **Безрисковая ставка (RUONIA):** для модели `capm`

## Параметры управления (UI)

| Элемент | Тип | Описание |
|---|---|---|
| Компания | Dropdown | Список уникальных тикеров из файла |
| Событие | Dropdown | Фильтруется по выбранному тикеру; подпись: `Анонс дивидендов (28.04.2015, 94 руб/акция)` |
| Модель | Dropdown | `mean_adjusted`, `market_model`, `capm` |
| Событийное окно — дней до | Slider | Количество торговых дней до t=0 (например, 10 → окно начинается за 10 дней) |
| Событийное окно — дней после | Slider | Количество торговых дней после t=0 |
| Оценочное окно — дней до начала событийного | Slider | Отступ: сколько дней между концом оценочного и началом событийного окна |
| Оценочное окно — длина | Slider | Количество торговых дней в оценочном окне |
| CPI-нормализация | Toggle (вкл/выкл) | Корректировать цену на инфляцию |

## Модели ожидаемой доходности

| Модель | Описание |
|---|---|
| `mean_adjusted` | Ожидаемая доходность = среднее за оценочное окно |
| `market_model` | OLS: r = α + β·r_IMOEX на оценочном окне |
| `capm` | r = rf + β·(r_IMOEX − rf), α = 0 |

## Визуализация

Три subplot-а с общей осью X (торговые дни от t=0):

### Subplot 1 (верхний, большой) — кривая CAR
- Линия накопленной аномальной доходности (CAR) по дням событийного окна
- Вертикальная пунктирная линия на t=0
- Подпись осей: X (общая) = "Торговые дни от события", Y = "CAR, %"
- **Hover:** дата (дд.мм.гггг), день недели, значение CAR, AR этого дня (дневная аномальная доходность)

### Subplot 2 (средний) — реальная цена акции
- Линия цены закрытия (CLOSE) в событийном окне
- Вертикальная пунктирная линия на t=0
- Подпись оси Y = "Цена, руб."
- **Hover:** дата, цена

### Subplot 3 (нижний, маленький) — объём торгов
- Barchart дневного объёма по дням событийного окна
- Цвета: нейтральный (до t=0), акцентный (после t=0)
- Подпись оси Y = "Объём торгов"
- **Hover:** дата, объём (без «t=»)

## Метрики-карточки

Отображаются над графиком. Каждая карточка имеет иконку (i) с tooltip-подсказкой при наведении.

| Метрика | Описание | Tooltip |
|---|---|---|
| CAR, % | Накопленная аномальная доходность за всё событийное окно | Сумма дневных аномальных доходностей (фактическая − ожидаемая) за все дни окна. Положительный = акция росла быстрее ожидания. |
| vol_ratio | Коэф. волатильности: std(после) / std(до) | > 1 — рынок нервничал после события, < 1 — успокоился |
| volume_ratio | Коэф. объёма: mean_vol(после) / mean_vol(до) | > 1 — объём вырос (активная реакция), < 1 — упал |

## Технические требования

- **Фреймворк:** Dash, `jupyter_mode='inline'`, авто-порт через `_DashApp` (как в `plot_utils.py`)
- **Ноутбук:** `notebooks/22_event_study_interactive.ipynb`
- Пересчёт — по нажатию кнопки «Рассчитать» (не на каждое изменение параметра)
- Дропдаун событий обновляется динамически при смене тикера (callback)

### Используемые модули из `core/nirs/`

| Модуль | Что используем |
|---|---|
| `loaders.py` | `load_events()`, `load_prices()`, `load_rf()` |
| `study.py` | `EventStudyRunner`, `EventStudyConfig`, `Event` |
| `models.py` | `MeanAdjustedModel`, `MarketModel`, `CAPMModel` (через фабрику в `study.py`) |

### Путь к данным (относительно ноутбука)

| Данные | Путь |
|---|---|
| Дивиденды | `../data/stocks/dividends_all.csv` |
| Котировки + IMOEX | `../data/stocks/` |
| RUONIA | `../data/stocks/RUONIA_RC_F11_01_2010_T13_03_2026.xlsx` |

### Логика работы

1. При старте: загрузить все данные один раз (`load_events`, `load_prices`, `load_rf`)
2. Callback 1: смена тикера → обновить список событий во втором дропдауне
3. Callback 2: кнопка «Рассчитать» → `EventStudyRunner.analyze_single_event()` → обновить график и карточки метрик
