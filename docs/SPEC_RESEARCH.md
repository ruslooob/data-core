# Исследования (Research)

Спецификация описывает **исследование** — организационную сущность, которая группирует стратегии, правила, окружения и прогоны бэктеста по логически связанной теме (например, «Защитные механики», «Cash management», «Аномалии дивидендных объявлений»).

Все термины описаны в [GLOSSARY.md](GLOSSARY.md). Реализационные детали (имена эндпоинтов, файлы, схема таблиц) — в коде.

---

## 1. Назначение

Без исследований стратегии и правила накапливаются в одном плоском пространстве. К нескольким десяткам артефактов теряется контекст — сложно вспомнить, какие из них относятся к одной задаче. Исследование возвращает структуру: явная граница, в которой ведётся работа над **одной целью**.

Конкретные роли исследования:

1. **Контекст работы.** Аналитик заранее выбирает исследование, и редакторы стратегий/правил/окружений, диалог запуска прогона, журнал прогонов показывают только относящееся к этому исследованию.
2. **Контейнер для отчёта.** К концу работы аналитик пишет выводы и получает структурированный текст со всем, что было сделано: артефакты, прогоны, метрики, заключение.
3. **Логическая граница.** Удаление исследования каскадно убирает его приватные артефакты и все прогоны. Параллельные исследования не пересекаются.

---

## 2. Сущность исследования

Исследование описывается тремя текстовыми полями.

| Поле | Назначение |
|---|---|
| **Имя** | Короткая фраза для переключателя и шапки отчёта. Уникально среди всех исследований. Можно переименовывать в любой момент. |
| **Описание идеи** | Свободный текст: что хотим выяснить, какие гипотезы планируем, контекст. Заполняется на старте, дополняется по ходу. Может быть пустым. |
| **Выводы** | Свободный текст с заключением. Заполняется к концу работы и попадает в подвал отчёта. Может быть пустым. |

Исследование **не имеет** формального статуса «открыто/закрыто/архивировано». Завершённость определяется тем, написаны ли выводы. Архивацию неактивных исследований добавим, если возникнет потребность.

### Системное исследование `Default`

Одно исследование с именем `Default` существует всегда. Это контейнер, к которому привязываются все ранее существовавшие прогоны при первом подключении новой схемы, и куда попадают новые пользователи, ещё не создавшие свои исследования. `Default` нельзя переименовать и нельзя удалить — он гарантирует, что у аналитика всегда есть на что переключиться при удалении любого другого исследования.

## 3. Приватные и общие сущности

Исследование ограничивает видимость **стратегий**, **правил** и **окружений**, а также служит контейнером для **прогонов**. Принадлежность управляется одной ссылкой на исследование у каждой из этих сущностей.

| Сущность | Семантика принадлежности |
|---|---|
| Стратегия, Правило, Окружение | **Опциональная**. Если ссылка пустая — сущность **общая**, видна во всех исследованиях. Если заполнена — **приватная**, видна только в одном указанном исследовании. |
| Прогон бэктеста, Результат бэктеста | **Обязательная**. Прогон всегда принадлежит ровно одному исследованию — тому, из которого был запущен. Общих прогонов не бывает. |

### Назначение общих сущностей

Общая сущность нужна, когда один и тот же артефакт логически переиспользуется в разных исследованиях:

- **Окружение** — типовая пара (тикер, период, стартовый капитал) объективна и не зависит от целей исследования. Создавать его заново в каждом — рутина.
- **Стратегия-baseline** (простой buy-and-hold) — может быть нужна как точка сравнения в нескольких разных исследованиях.
- **Базовое правило** (например, «купить тикер на весь свободный кэш») — может входить в стратегии разных исследований.

### Видимость в интерфейсе

В исследовании по умолчанию показываются **только приватные** сущности — рабочий список без шума параллельных задач. У каждого редактора есть переключатель «Показать общие». При его включении общие появляются в списке вместе с приватными и помечаются визуально как общие.

### Перевод между общим и приватным состоянием

Аналитик может расширять или сужать видимость существующей сущности:

- **Сделать общую сущность приватной** для текущего исследования — разрешено, **если** на эту сущность не ссылается ни один прогон, принадлежащий другому исследованию. Иначе чужой прогон стал бы ссылаться на невидимую ему сущность.
- **Сделать приватную сущность общей** — разрешено всегда; это только расширяет видимость.

Перевод не запрещает дальнейшие изменения (общая → приватная → снова общая), пока сохраняется инвариант видимости относительно прогонов.

### Удаление общей сущности

Удаление общей сущности разрешено, **если** на неё не ссылается ни один прогон ни в одном исследовании. Симметрично переводу: пока есть зависимости, состояние сохраняется.

## 4. Активное исследование как контекст работы

Аналитик в любой момент работает в контексте ровно одного **активного исследования**. Это состояние:

- **Обязательное.** Без выбранного активного исследования основные функции приложения недоступны: нельзя создавать стратегии, правила, окружения, нельзя запускать прогоны, нельзя смотреть журнал прогонов. Запрет действует и в UI (виджеты заблокированы или экран блокирует работу), и в API (запросы без идентификатора активного исследования отклоняются).
- **Сохраняемое между сессиями.** Активное исследование запоминается на стороне клиента и переживает перезагрузку страницы. Бэкенд сам по себе не хранит «текущее исследование пользователя» — это контекст конкретного UI-сеанса.
- **Переключаемое.** Аналитик переключается на другое исследование в любой момент. После переключения весь зависящий UI перерисовывается под новый контекст.
- **Привязка прогона.** Когда аналитик запускает прогон в активном исследовании `R`, прогон получает `research_id = R` независимо от того, общие или приватные у него стратегия и окружение. Тот же общий baseline, прогнанный из двух разных исследований, даёт два разных результата в двух разных журналах прогонов.

Виджеты, не связанные с бэктестом (просмотр свечей, событийный анализ, поиск прецедентов), **не зависят** от активного исследования: они работают с общими данными приложения и доступны всегда.

## 5. Жизненный цикл

Типовой сценарий:

1. **Создание.** Аналитик нажимает «Создать исследование», вводит имя и (опционально) описание идеи. UI автоматически переключается на новое исследование.
2. **Работа.** В рамках исследования создаются приватные стратегии и правила, при необходимости — приватные окружения. Запускаются прогоны, читаются метрики и журналы сделок. Описание идеи может дополняться по мере появления новых наблюдений.
3. **Завершение.** Аналитик заполняет раздел выводов. Формальной кнопки «закрыть» нет — наличие текста выводов и есть критерий завершённости.
4. **Отчёт.** Аналитик получает текстовый отчёт по исследованию (см. раздел 7).
5. **Удаление.** Исследование можно удалить вручную (с подтверждением) — каскадно удаляются все приватные стратегии, правила, окружения и все прогоны. Общие сущности, привязанные к нему через прогоны, остаются. `Default`-исследование удалить нельзя.

### Пример

Аналитик хочет проверить, насколько защитные механики (trailing stop, take-profit) портят/улучшают buy-and-hold на длинной истории.

- Создаёт исследование `Защитные механики`, в описании фиксирует гипотезу.
- Базовый buy-and-hold уже есть как **общая** стратегия. Включает «Показать общие», использует её как baseline.
- Создаёт **приватное** правило «trailing stop −15% от пика equity» в этом исследовании. Создаёт приватные стратегии-варианты, привязывая их к разным комбинациям защитных правил.
- Запускает прогоны на общем окружении `LKOH full history 2002-2025`. Прогоны попадают в журнал именно этого исследования.
- Дополняет описание наблюдениями. По завершении пишет выводы.
- Открывает виджет отчёта, скачивает его и публикует.

## 6. Что не входит в исследование

Исследование группирует **результаты пользовательской работы**, но не управляет данными приложения. Вне его границ остаются:

- **Данные предметной области**: котировки, дивиденды, события, теги, корпоративные действия. Это общие данные, доступные во всех исследованиях.
- **Прецедентные запросы (PQL)**: каталог сохранённых запросов и системных рецептов общий, не привязан к исследованию.
- **Виджеты для исследования рынка** (просмотр свечей, индексов, событийный анализ, прецедент-эдитор): работают с общими данными и не требуют активного исследования.
- **Версионирование артефактов**: исследование не хранит истории правок стратегий и правил. Изменение содержимого правила влияет на все будущие прогоны, в которых оно используется.
- **Права доступа**: разделения по пользователям нет — приложение однопользовательское.

Если в будущем потребуется «исследовательское» расширение какого-либо из этих слоёв (например, приватный набор PQL-запросов), это будет отдельной итерацией с собственной спекой.

## 7. Отчёт по исследованию

Отчёт — основной результат исследования для внешнего читателя. На данный момент реализован **в минимальном объёме**: единый эндпоинт экспорта, возвращающий журнал прогонов исследования в выбранном формате. Подходящие форматы — таблица для импорта в Excel/Python и печатный документ для подачи. Логика отчёта живёт на бэкенде — единая точка истины по структуре, формат выбирается параметром.

Виджет фронта — тонкий: выпадающее меню «Скачать ▾» с пунктами по доступным форматам. Превью отчёта внутри виджета не делается — содержимое читается в выбранном инструменте (Excel, PDF-просмотрщик).

### На будущее: журнал исследования

Запланирован полноценный журнал — хронологический поток размышлений аналитика и привязанных к ним прогонов. Аналитик собирает структуру не из ручных шаблонов, а из заметок и автоматических событий (запуск прогона, изменение стратегии и т. п.). Это превращает отчёт в инструмент, похожий на ноутбук «текст + результаты». Текущая модель данных не блокирует это расширение.

## 8. Закрытые дизайн-вопросы

Вопросы, которые обсуждались при проектировании и закрыты решением. Приведены коротко — для понимания «почему так», без претензии на полную аргументацию.

1. **Модель группировки.** Жёсткая принадлежность с опциональным «общим» состоянием. Тег-модель отвергнута: размывает границу исследования и делает отчёт неоднозначным.
2. **Цитирование чужих прогонов.** В этой итерации не делается. На будущее — механизм цитирования прогонов из других исследований в кастомном отчёте, без перемещения.
3. **Окружения — общие или приватные.** Гибрид: общие по умолчанию (для типовых пресетов), приватные по необходимости (для исследовательских песочниц).
4. **Состояние общая ↔ приватная.** Можно менять в обе стороны при условии сохранения инварианта видимости относительно прогонов.
5. **Видимость в UI по умолчанию.** Только приватные. Общие появляются по тоггл-переключателю.
6. **Принадлежность прогона при общих компонентах.** Прогон принадлежит активному исследованию на момент запуска. Это даёт возможность одну и ту же общую стратегию прогонять из разных исследований и видеть результаты в их журналах.
7. **Поле «гипотеза».** Не вводится. Исследование — группа гипотез, а не одна; формулирование гипотез остаётся в свободном поле описания.
8. **Признак системного исследования.** Захардкоженное имя `Default` без отдельного флага в схеме.
9. **Логика отчёта.** На бэкенде. Одна точка истины, расширяется на новые форматы вывода через варианты эндпоинта.
10. **Миграция накопленных данных.** Все стратегии/правила/окружения становятся общими; все прогоны попадают в `Default`-исследование.
11. **Поведение при пустом активном исследовании.** Заблокировать основной функционал и заставить выбрать или создать. По умолчанию активным становится `Default`.
