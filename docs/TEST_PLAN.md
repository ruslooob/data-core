# План покрытия тестами

## P0 — критично, ломают результаты

### expected_return_models.py
- MeanAdjustedModel: fit запоминает среднее, predict возвращает константу на все даты
- MarketModel: fit находит α и β, predict возвращает α + β·r_market
- CAPMModel: fit находит β, predict возвращает rf + β·(r_market − rf)
- Все модели: kwargs не вызывают ошибку (лишние аргументы проглатываются)

### stock_data_provider.py
- get_log_returns: возвращает pd.Series с DatetimeIndex, значения — логдоходности
- Корректировка сплитов: цена до сплита делится на ratio

### event_study.py — outlier_threshold
- С фильтрацией estimation_std <= чем без
- outliers_removed > 0 при наличии выбросов
- outliers_removed = 0 при outlier_threshold=None

### precedent_engine — схема
- Видимая схема создаётся: таблицы `events`, `tags`, `event_tags`, представление `tagged_events`, функция `car()` зарегистрированы
- Колонки таблиц соответствуют ожидаемой структуре
- Простой SELECT по `tagged_events` возвращает строки
- Эквивалентность короткой формы (через `tagged_events`) и явного JOIN по тегам

### precedent_engine — UDF car()
- Численное равенство SQL-вызова и прямого вызова `EventStudy.analyze` для всех трёх моделей (mean_adjusted, market_model, capm) с допуском 1e-12
- Дефолтная модель совпадает с `market_model`
- NULL на несуществующем тикере и слишком ранней дате (без эксепшена)
- Кастомные окна и оценочное окно через named-аргументы

### Исследования (Research) — схема
- Таблица `research` создана; системный `Default` существует
- У стратегий/правил/окружений есть колонка `research_id` (NULL = общая)
- У прогонов `research_id` обязателен и привязан к существующему исследованию
- FK с ON DELETE CASCADE: удаление исследования каскадно убирает приватные артефакты и прогоны
- UNIQUE-инвариант имени: уникально в пределах одного исследования + глобально среди общих

### Исследования — REST CRUD
- GET списка исследований включает `Default`
- POST создаёт новое; дубликат имени → 409; пустое имя → 400
- PATCH меняет имя/описание/выводы поодиночке или вместе
- Защита `Default`: переименование запрещено, удаление запрещено
- DELETE прочих: каскадно удаляются приватные стратегии/правила/окружения и прогоны

### Исследования — фильтрация и привязка прогона
- Listing-эндпоинты стратегий/правил/окружений/прогонов требуют `researchId`; без него → 422
- `includeCommon=false` (по умолчанию) — только приватные; `=true` — приватные + общие
- Прогоны фильтруются строго по исследованию (общих прогонов не существует)
- POST `/api/backtest/run` обязательно принимает `researchId`; запись `backtest_results.research_id` ему равна
- Несуществующий `researchId` в запуске → 404

### Исследования — перевод между общей и приватной видимостью
- Happy path: общая → приватная → общая для всех трёх типов сущностей
- Несуществующий целевой `researchId` → 404
- Блок 409: общую сущность нельзя сделать приватной для исследования X, если на неё ссылаются прогоны *других* исследований (включая косвенную ссылку «правило → стратегия → прогон»)
- Перевод приватной → общей разрешён всегда

### Исследования — экспорт отчёта
- GET `/api/research/{id}/export?format=csv` возвращает `text/csv; charset=utf-8` с BOM и плоской таблицей всех прогонов исследования (стратегия, окружение, период, 7 метрик, дата создания)
- GET `/api/research/{id}/export?format=pdf` возвращает 501 (не реализовано — заглушка)
- Неизвестный `format` → 400
- Несуществующее исследование → 404
