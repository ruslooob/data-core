# Спецификация: прогноз по прецедентам (Precedent Forecast)

> **Статус:** драфт. Центральный аналитический виджет в линии «прецедент → анализ». Принимает набор прецедентов из «Поиска прецедентов» (см. [SPEC_PRECEDENT_SEARCH_DRAFT.md](SPEC_PRECEDENT_SEARCH_DRAFT.md)) и строит прогноз ожидаемого эффекта на тикер для текущего или гипотетического события.

---

## Назначение

Сформулировать гипотезу о новом или гипотетическом событии и получить прогноз ожидаемого отклика рынка на основе того, как рынок реагировал в **похожих исторических случаях** (прецедентах). Это центральный результат линии работы «интеллектуальный анализ влияния событий через поиск прецедентов».

Виджет отвечает на вопрос: «Если ситуация похожа на найденные прошлые случаи — какой реакции инструмента ожидать?»

Методологически это вариант **case-based reasoning** — стандартного подхода в академической литературе для финансов и юриспруденции. Не магия, не ML — статистика по выборке исторических случаев.

---

## Что показывает виджет

Главное представление — **профиль CAR(t)**: график того, как ожидаемое накопленное аномальное отклонение цены инструмента развивается во времени относительно дня события.

- По оси X — дни относительно события (например, от −5 до +30).
- По оси Y — медианный CAR по выборке прецедентов.
- Полоса вокруг линии — доверительный интервал (например, 95%).
- Pre-event сегмент (отрицательные дни) — для проверки утечки информации до события.

Что пользователь видит сразу:
- Где пик эффекта (например, на 3-й день после события).
- Когда эффект стабилизируется или откатывается.
- На каких горизонтах сигнал тонет в шуме (доверительный интервал расширяется).
- Есть ли pre-event drift, указывающий на утечку.

Дополнительно сбоку — таблица «значения для типичных горизонтов»: 1, 5, 10, 20 дней. Для тех, кому нужно одно конкретное число.

---

## Откуда берутся данные

Виджет читает набор прецедентов из логической группы (его выдаёт «Поиск прецедентов»). Для каждого прецедента запускается event study на интересующем тикере, и все полученные CAR-кривые агрегируются.

Виджет **сам события не ищет** — это разделение ответственности с «Поиском прецедентов». Один и тот же набор прецедентов параллельно используется в Robustness Check, маркерах на графике, бэктесте.

---

## Почему окно не выбирается

Размер окна — критичный параметр event study, и заставлять пользователя выбирать его — плохой UX:
- Разные гипотезы требуют разных горизонтов (±1 для мгновенной реакции, ±20 для среднесрочного эффекта).
- Пользователь часто не знает, какое окно «правильное» для его гипотезы.
- Зафиксировать одно окно — значит скрыть от пользователя, что прогноз сильно зависит от него.

Решение: **не давать выбирать окно вообще**, а показывать профиль CAR(t) на широком горизонте сразу. Это:
- Снимает вопрос «какое окно выбрать».
- Делает зависимость прогноза от горизонта явной — пользователь видит, как CAR меняется со временем.
- Отвечает на скрытую претензию «при разных окнах разный прогноз» прямой визуализацией.
- Является стандартом event study литературы (cumulative average abnormal returns plot).

---

## Связь с другими виджетами

| Виджет | Связь |
|--------|-------|
| **Поиск прецедентов** | Источник набора. Без «Поиска прецедентов» в группе виджет не работает. |
| **Event Study** (одиночный) | Деталь по одному прецеденту из набора. Прогнозный виджет — агрегат, Event Study — единичный разбор. |
| **Robustness Check** | Соседний виджет с другой целью: прогноз отвечает «какой эффект ожидать», robustness — «устойчив ли этот прогноз к выбору параметров методологии». Делят общее вычислительное ядро (агрегация CAR по набору). |
| **Бэктест** | Out-of-sample валидация прогноза: «если бы знал заранее, что эти 12 случаев похожи на текущее событие — какова была бы доходность?» |

## Открытые вопросы

> **Отложены до отдельной сессии обсуждения.** Базовая концепция виджета зафиксирована, детали методологии — следующая итерация.

1. **Какая статистика отображается как центральная линия** — медиана, среднее, что-то другое? Влияет на устойчивость к выбросам.
2. **Тип доверительного интервала** — bootstrap, параметрический? Связано с тем, какой статтест считается корректным для CAR.
3. **Учитывать ли вес прецедента** (оценку семантической близости из «Поиска прецедентов») при агрегации? Если да — какая взвешенная статистика (взвешенная медиана, взвешенное среднее, экспоненциальное взвешивание, отсечка по порогу близости).
4. **Каков горизонт прогноза по умолчанию** — от какой `t_min` до какой `t_max`?
5. **Что показывать, если выборка прецедентов слишком мала** (например, top-K = 3)? Скрывать виджет, показывать предупреждение, рисовать с большим доверительным интервалом?
6. **Поведение при отсутствии тикера в группе** — виджет должен куда-то проецировать CAR. Это ведущий график группы? Явный селектор тикера в виджете? И тикер, и сектор?

---

## Закрытые вопросы

- **Имя виджета** — «Прогноз по прецедентам» / «Precedent Forecast».
- **Какой размер окна выбирает пользователь** — никакой. Виджет показывает профиль CAR(t) на широком горизонте, что делает зависимость прогноза от окна явной и снимает выбор у пользователя.

---

## Не входит в этот документ

- Алгоритм event study (модели ожидаемой доходности, расчёт CAR) — уже описан в существующей документации.
- Алгоритм семантического поиска — в «Поиске прецедентов».
- Backtest валидации прогноза — отдельная спецификация (может быть, в существующей SPEC_BACKTEST).
