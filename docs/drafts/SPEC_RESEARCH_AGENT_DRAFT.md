# Спецификация: автономный исследовательский агент (Research Agent)

> **Статус:** каркас драфта. Содержательное обсуждение отложено — здесь только записаны исходные идеи и зацепки для будущего раунда.

---

## Исходная идея

Пользователь формулирует исследовательскую гипотезу на естественном языке («покупать ЛУКОЙЛ на дивидендном гэпе», «когда война — покупай золото»). LLM-субагент, получая skill с описанием возможностей системы (поиск прецедентов, event study, бэктест), **автономно** прогоняет цепочку шагов и возвращает аналитический отчёт.

Цель — превратить систему в **LLM-friendly платформу**, где субагент может работать с данными без посредничества человека на каждом шаге.

---

## Что агент мог бы делать

- Принять гипотезу пользователя.
- Сформулировать поисковый запрос (PQL или семантический) для нахождения релевантных прецедентов.
- Запустить Event Effect Analysis для оценки ожидаемого эффекта (профиль forecast и анализ устойчивости).
- Если эффект статистически значим — построить торговое правило для бэктеста.
- Запустить бэктест на исторических данных.
- Собрать итоговый отчёт: что искал, что нашёл, какой прогноз, как отработал бэктест, выводы.

## Открытые вопросы (для будущего обсуждения)

1. **Формат skill** — как описывается набор инструментов агента: список функций, документация в свободном тексте, JSON Schema, какой-то DSL?
2. **Граница автономности** — где агент принимает решения сам, а где требует подтверждения пользователя? Например: «нашёл 3 прецедента — мало, продолжать?»
3. **Какой LLM используется** — внешний (Anthropic/OpenAI), локальный, выбор пользователя?
4. **Как валидировать результаты агента** — нужна ли цепочка размышлений в отчёте, как защитить от галлюцинаций?
5. **Защита диплома** — что в этой части является собственной разработкой автора, а что — интеграцией готового LLM? Это важный момент для научного руководителя: ядро должно быть собственным, агент — оркестратором поверх.
6. **UI агента** — отдельный виджет? Чат-интерфейс? Запуск через slash-command? Интеграция с группой?
7. **Сохранение результатов прогонов агента** — где хранится история «гипотеза → отчёт»?
8. **Стоимость и лимиты** — учитывая, что каждый прогон агента стоит токенов LLM, нужны ли ограничения?

## Связи с другими частями системы

| Компонент | Как использует |
|-----------|----------------|
| **Поиск прецедентов** | Агент формирует запросы и читает результат как инструмент. |
| **Event Effect Analysis** | Агент запускает и интерпретирует индивидуальные CAR, forecast и heatmap чувствительности. |
| **Бэктест** | Агент строит правила (триггер + действие) и запускает прогоны. |
| **Глоссарий проекта** | Источник терминов для skill — агент должен говорить на языке проекта. |

## Не входит в этот документ

- Конкретный формат skill — определится после первой итерации обсуждения.
- Выбор модели и провайдера LLM — реализационная деталь.
- Документация по skill — пишется отдельно, после стабилизации спецификации.
