# Бэклог

## Рефакторинг

### Обобщить `DividendEvent` → `Event`
- Сейчас в `core/models.py` единственный класс события — `DividendEvent` с полями `ticker, event_date, dividend, year`
- Глоссарий описывает общий концепт `Event` — дискретный момент новой информации, не обязательно дивидендный
- Когда появятся другие типы событий (санкции, отчётности, ставка ЦБ), разделить на `Event` (общий) + конкретные подтипы или добавить поле `event_type`
- Подождать конкретного второго use-case, чтобы не делать абстракцию ради абстракции

### Перевести `/api/events` на таблицу `events` DuckDB-базы
- Сейчас эндпоинт `/api/events` читает CSV `data/stocks/dividends_all.csv` через `DividendDataProvider.load_dividends()` и возвращает только даты `announcement_date` (поле `payment_date` игнорируется)
- В таблице `events` уже лежат **обе** даты на каждый дивиденд (объявление + выплата) — добавлены скриптом `scripts/import_dividends_to_db.py`
- Из-за рассинхрона виджет Event Study показывает только объявления, редактор PQL — обе даты
- Переписать эндпоинт на чтение из таблицы `events` (через тег `DIVIDEND_ANNOUNCEMENT` / `DIVIDEND_PAYMENT`), убрать прямое чтение CSV из API
- После этого можно будет удалить `DividendDataProvider.load_dividends` (если больше нигде не используется)

## Новые инструменты

### Виджет фильтра событий
- Центральный источник событий для логической группы
- SQL-подобный запрос (DSL) + ручная корректировка чекбоксами
- Спека: `docs/SPEC_EVENT_FILTER.md`

### Язык поиска прецедентов (PQL) — пост-MVP расширения
- Доп. встроенные метрики как UDF: `vol_ratio`, `volume_ratio`, `pre_event_car`, `drawdown`
- Pаметры расчёта на уровне запроса (аналог SET) — макрос с глобальной переменной DuckDB
- Пользовательские именованные метрики (аналог DEFINE) — через WITH/CTE
- Сохранение прецедентов как именованных шаблонов между сессиями (отдельная таблица в БД)
- Интеграция с логической группой виджетов: трансляция результатов поиска
- Подсветка строки/колонки в textarea при ошибке (требует структурированной позиции от движка SQL — DuckDB пока её надёжно не отдаёт)
- Спека: `docs/SPEC_PRECEDENT_LANGUAGE.md`. Старый черновик `docs/ANOMALY_DSL.md` — устарел, заменён.

### Прове��ка устойчивости (Robustness Check)
- Тепловая карта: средний CAR по набору событий × вариации параметров (окно, модель)
- Отвечает на вопрос: устойчив ли эффект или это артефакт конкретных параме��ров
- Спека: `docs/ROBUSTNESS_CHECK.md`

### Бэктест торговых стратегий
- Прогон стратегий на исторических данных с расчётом метрик (P&L, max drawdown, Sharpe, win rate)
- Пользователь находит закономерность через event study / anomaly detector → проверяет как стратегию

### Новый flow приложения
- Текущая модель виджетов на полотне не подходит для directed workflow (anomaly detector → event study → бэктест)
- Обсудить переход на экраны/вкладки с сохранением контекста между инструме��тами
